# docs 폴더 규칙

`docs/`는 krx-sprint의 개발/운영 문서와 변경 계획서(Implementation Plan)를 관리한다.

## 문서의 두 종류

| 종류 | 파일 | 수명 |
|---|---|---|
| **살아있는 문서** | `ROADMAP.md`, `데이터수집_스펙_v2.md`, `백테스트_설계_v1.md`, `백테스트_설계_v2.md`, `COMMANDS.md` | 영구. 계속 갱신한다 |
| **계획서** | `plans/PLAN_*.md` | **임시.** 사용자가 주기적으로 전부 삭제한다 |

각 문서의 SoT 역할:

- `ROADMAP.md` — 진행 상태, Phase별 산출물과 설계 계약
- `데이터수집_스펙_v2.md` — 수집 단계의 **실측 기록**(§0·§8). 기억이 아니라 실측으로만 고친다
- `백테스트_설계_v1.md` — 데이터 계층·비용·체결 가정, 확정된 결정(§13), v1 실행 결과와 기각 근거(§14)
- `백테스트_설계_v2.md` — 종목 선정·진입 재설계, 확정된 결정과 탈락안(§7), v2 실행 결과와 기각 근거(§5).
  **설계 문서는 덮어쓰지 않고 버전을 올린다** — 기각 기록이 "이미 해봤다"의 근거다
- `COMMANDS.md` — 모든 실행 명령어

## 계획서

- 작성·갱신 절차는 `/plan` 스킬이 SoT다. 계획서를 만들거나 고칠 때 해당 스킬을 따른다.
- **살아있는 문서에서 계획서를 링크하지 않는다.** 계획서는 주기적으로 삭제되므로 링크가 깨진다.
  필요한 내용은 복사해 살아있는 문서가 자립하게 만든다.
- **Done 처리 전에 근거를 살아있는 문서로 승격한다.** 판단 기준은
  "이 계획서를 지금 지워도 잃는 것이 없는가". 상세는 `/plan` 스킬의 "근거 승격" 절.
- `plans/.gitkeep`은 지우지 않는다 — 디렉토리가 사라지면 계획서 게이트 훅이 비활성화된다.
