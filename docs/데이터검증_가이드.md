# 수집 데이터 수기 검증 가이드

> 자동 품질 리포트(`scripts/data/check_snapshot_quality.py`)가 **잡지 못하는 것**을 사람이 확인하기 위한 절차서.
> 검사 규칙과 결과는 [데이터수집_스펙_v2.md](데이터수집_스펙_v2.md) §8을 참고한다.

## 왜 수기 검증이 필요한가

자동 리포트는 **내부 일관성**만 본다. "시총 = 종가 × 상장주식수"가 470만 행 전부 맞아도, 그 값들이 통째로 다른 날짜의 것이거나 시장 실제와 어긋날 수 있다. 이를 배제하려면 **외부 기준과 대조**해야 하고, 그건 사람이 한다.

현재 자동 검사에 등록된 외부 기준값(앵커)은 **삼성전자 2021-01-04 한 건**뿐이다. 이 가이드로 확인한 값을 앵커로 추가할수록 이후 검증이 자동화된다(§결과 남기기).

## 검증 시점

**2단 수정주가 수집(ROADMAP Phase 5)과 백테스트 착수 전**이 마지막 저비용 시점이다. 1단 데이터가 스크리닝의 입력이므로, 여기가 틀리면 이후 단계가 전부 오염된다. 저장 파일은 불변 계약이라 늦게 발견할수록 되돌릴 파일이 많아진다.

## 대조할 외부 소스

| 소스 | 용도 |
|---|---|
| 네이버 금융 종목 페이지 → **일별 시세** | OHLCV·거래량 대조 (원본가 기준이라 우리 데이터와 직접 비교 가능) |
| 네이버 금융 → 국내증시 → **거래상위** | 특정일 거래대금 상위 종목 대조 |
| KRX 정보데이터시스템 → **상장폐지 종목** | 폐지일 확인 |
| DART 전자공시 | 증자·감자·액면분할 공시일 확인 |
| 증권사 HTS/MTS 차트 | 전반적 눈 대조 |

> 주의: 네이버 차트의 **수정주가 표시 옵션을 끄고** 대조한다. 우리 1단 데이터는 원본가다(스펙 §7.2).

## 1. 폐지 종목 보존 — 생존편향 검증

**왜 중요한가**: 전략 대상이 테마 대장주라 급등 후 관리·폐지되는 경우가 드물지 않다. 폐지 종목이 빠지면 성과가 조용히 부풀려진다(스펙 §3.2).

**확인할 것**: 폐지된 종목의 데이터가 **폐지 직전까지 남아 있는가**. 그리고 마지막 등장일이 실제 폐지 시점과 맞는가.

```bash
# 품질 리포트가 폐지로 판정한 종목 목록 (최근 순)
poetry run python -c "
import pandas as pd, glob
csv = sorted(glob.glob('storage/cache/quality_report_*.csv'))[-1]
df = pd.read_csv(csv, dtype=str)
d = df[df['category']=='폐지 종목'].copy()
d['last'] = d['detail'].str.extract(r'마지막 등장 (\S+)')
print(f'폐지 판정 {len(d)}종목')
print(d[['target','last']].sort_values('last', ascending=False).head(20).to_string(index=False))
"
```

**대조 방법**: 목록에서 아는 종목을 골라 KRX 상장폐지 목록에서 폐지일을 확인한다.

**합격 기준**: 우리 데이터의 마지막 등장일이 **정리매매 종료일 근처**여야 한다. 폐지일보다 한참 이르면 데이터가 중간에 끊긴 것이다.

## 2. 신규 상장 — 첫날부터 있는가

**왜 중요한가**: IPO 직후 급등은 테마를 만든다. 상장 첫날이 빠지면 그 구간을 못 본다.

```bash
# 특정 티커가 처음 등장한 날짜를 찾는다
poetry run python -c "
from krx_sprint.collect.snapshot_store import list_collected_dates, load_snapshot
TICKER = '432470'          # ← 확인할 티커로 교체
for d in sorted(list_collected_dates()):
    if TICKER in set(load_snapshot(d)['ticker']):
        print('첫 등장:', d)
        s = load_snapshot(d)
        print(s[s['ticker']==TICKER].to_string(index=False))
        break
"
```

**대조 방법**: 네이버 금융에서 그 종목의 상장일을 확인한다.

**합격 기준**: 첫 등장일 = 상장일. 그리고 그날 시가·종가·거래량이 네이버 일별 시세와 일치.

## 3. 거래대금 — 전략의 핵심 지표

**왜 중요한가**: 주도테마·대장주 스크리닝이 **거래대금**으로 이루어진다(스펙 §2). 이 값이 틀리면 종목 선정 자체가 무너진다. 반드시 **원본가 기준**이어야 하며 수정주가로 계산된 값이면 안 된다.

```bash
# 특정일 거래대금 상위 20종목
poetry run python -c "
from datetime import date
import pandas as pd
from krx_sprint.collect.snapshot_store import load_snapshot
TARGET = date(2021, 1, 11)   # ← 확인할 일자로 교체
names = pd.read_csv('storage/names.csv', dtype=str).set_index('ticker')['name'].to_dict()
df = load_snapshot(TARGET)
top = df.nlargest(20, 'value')[['ticker','market','close','change_rate','volume','value']].copy()
top.insert(1, 'name', top['ticker'].map(names))
top['value_억'] = (top['value']/1e8).round(0).astype(int)
print(f'{TARGET} 거래대금 상위 20 (전체 {len(df)}종목)')
print(top[['ticker','name','market','close','change_rate','value_억']].to_string(index=False))
"
```

**대조 방법**: 네이버 금융 → 국내증시 → 거래상위(해당 일자) 또는 HTS의 거래대금 순위.

**합격 기준**: 상위 종목 **구성과 순서**가 일치하고 금액도 맞아야 한다. 순서만 어긋나면 동순위 처리 차이일 수 있으니 금액을 본다.

> 폐지 종목이 이름 없이 티커만 나오는 것은 정상이다. `names.csv`는 최신 상장분 기준이라 폐지 종목명이 없다.

## 4. 개별 종목 OHLCV — 차트 눈 대조

**왜 중요한가**: 가장 직관적인 검증이다. 시가·고가·저가는 스윙과 전저점 판정에, 종가는 신호 산출에 쓰인다.

```bash
# 특정 종목의 기간 시세
poetry run python -c "
from datetime import date
from krx_sprint.collect.snapshot_store import list_collected_dates, load_snapshot
TICKER, START, END = '005930', date(2021,1,4), date(2021,1,15)   # ← 교체
for d in sorted(x for x in list_collected_dates() if START <= x <= END):
    r = load_snapshot(d)
    r = r[r['ticker']==TICKER]
    if r.empty: print(d, '없음'); continue
    s = r.iloc[0]
    print(f\"{d} 시{s['open']:>8,} 고{s['high']:>8,} 저{s['low']:>8,} 종{s['close']:>8,} 거래량{s['volume']:>12,} 등락{s['change_rate']:>7.2f}%\")
"
```

**대조 방법**: 네이버 금융 종목 → 시세 → 일별 시세 표. **수정주가 옵션은 끈다.**

**합격 기준**: 시/고/저/종/거래량이 **완전히 일치**해야 한다. 하나라도 다르면 원인을 규명한다.

**권장 대조 구간** (극단값이라 어긋나면 눈에 띈다):

| 일자 | 이유 |
|---|---|
| 2020-03-19 | 코로나 저점. 대부분 종목이 급락 |
| 2020-03-13 | 서킷브레이커 발동일 |
| 2021-01-11 | 코스피 최고가 부근, 거래대금 극대 |
| 2022-09-30 | 2022 하락장 저점 부근 |

## 5. 증자·감자·액면분할 — 등락률 왜곡 확인

**왜 중요한가**: 기준봉 판정이 "당일 상승률 Y% 이상"인데, 감자 후 재개일 같은 날은 원본가 등락률이 수천 %로 찍힌다. 실제로 `052670` 2026-02-09가 **+29,948%**(1,500:1 감자)로 기록돼 있다. 걸러내지 않으면 **가짜 기준봉**이 된다(스펙 §10.5).

```bash
# 상장주식수가 급변한 종목·일자 목록 (품질 리포트가 자동 탐지)
poetry run python -c "
import pandas as pd, glob
csv = sorted(glob.glob('storage/cache/quality_report_*.csv'))[-1]
df = pd.read_csv(csv, dtype=str)
d = df[df['category']=='상장주식수 급변']
print(f'상장주식수 급변 {len(d)}건')
print(d[['target','detail']].head(30).to_string(index=False))
"
```

**대조 방법**: DART에서 해당 종목의 그 시점 공시(유상증자·무상증자·감자·주식분할)를 확인한다.

**합격 기준**: 목록의 일자가 실제 공시 효력일과 맞아야 한다. **이 목록 자체가 백테스트에서 제외할 일자 명단**이 된다.

## 6. 시점별 시가총액 — Point-in-Time 확인

**왜 중요한가**: 시총은 유니버스 필터(초소형주 배제)에 쓰인다. "오늘 주식수 × 과거 종가" 같은 오염이 있으면 필터가 어긋난다(스펙 §3.1).

```bash
# 특정일 시가총액 상위 10
poetry run python -c "
from datetime import date
import pandas as pd
from krx_sprint.collect.snapshot_store import load_snapshot
TARGET = date(2020, 3, 19)   # ← 교체
names = pd.read_csv('storage/names.csv', dtype=str).set_index('ticker')['name'].to_dict()
df = load_snapshot(TARGET)
top = df.nlargest(10, 'market_cap')[['ticker','close','shares','market_cap']].copy()
top.insert(1, 'name', top['ticker'].map(names))
top['시총_조'] = (top['market_cap']/1e12).round(1)
print(f'{TARGET} 시총 상위 10')
print(top[['ticker','name','close','시총_조']].to_string(index=False))
"
```

**대조 방법**: 그 시점 시총 순위 기사나 자료와 비교한다. 순위 변동이 큰 시기(2020~2021 배터리·바이오 급등)를 고르면 판별력이 높다.

**합격 기준**: 상위 구성이 **그 시점 기준**이어야 한다. 현재 시총 순위와 같다면 오염을 의심한다.

## 결과 남기기 — 확인한 값을 자동 검사로 편입

수기 대조로 확인된 값은 **앵커로 등록**해 다음부터 자동 검증되게 한다.

1. [데이터수집_스펙_v2.md](데이터수집_스펙_v2.md) §3.1에 확인한 값을 기록 (종목·일자·종가·상장주식수·시가총액)
2. `src/krx_sprint/collect/quality.py`의 `ANCHORS`에 `AnchorRecord` 추가
3. `poetry run python scripts/data/check_snapshot_quality.py` 재실행 → 통과 확인

이 절차를 반복하면 수기 검증 부담이 계속 줄어든다.

## 이상을 발견했을 때

**데이터를 고치지 않는다.** 보간·수정은 금지다(루트 CLAUDE.md). 해당 일자를 재수집한다.

```bash
# 1. 문제 일자 파일 삭제 (불변 계약상 덮어쓰기가 불가하므로 삭제가 필요)
rm storage/snapshots/2021/20210111.parquet

# 2. 재수집 — 삭제된 일자만 다시 받는다
poetry run python scripts/data/collect_snapshots.py

# 3. 품질 재확인
poetry run python scripts/data/check_snapshot_quality.py
```

재수집해도 같은 값이면 KRX 원본이 그러한 것이므로, **처리 방침을 스펙 §8에 기록**하고 백테스트에서 다루도록 넘긴다.
