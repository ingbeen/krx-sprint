## 1. 범위와 원칙

### 1.1 목표

2019-01-01 ~ 2026-07-27 구간에서 "주도테마 대장주 눌림목" 전략의 **비용 차감 후 순기대값**이 양수인지를
판정할 수 있는 백테스트 엔진을 만든다. 스펙 §1의 전략 정의를 코드로 옮기고, 수집 단계에서 발견된
처리 규칙(§3)을 하나도 빠뜨리지 않는 것이 성공 조건이다.

### 1.2 비목표 (이번 범위 밖)

- 분봉·호가 데이터 기반 정밀 체결 시뮬레이션 (일봉 + 예약매매 가정으로 간다)
- 실시간 운용·주문 연동 (ROADMAP Phase 4 증분 업데이트가 선행 조건)
- 관리종목·투자경고 필터 (이력 미수집 — 필요해지면 별도 수집)
- PIT 종목명 소급 (`names.csv`는 최신 매핑만 담는다. 결과 해석용으로만 쓴다)
- 포트폴리오 최적화·레버리지·공매도

### 1.3 절대 원칙

1. **look-ahead 금지**: 신호는 D-1 종가까지의 정보로만 산출하고, 집행은 D일에 예약주문으로 한다.
   당일 종가로 당일 매매를 가정하지 않는다 (스펙 §10.1).
2. **원본가/수정주가 분리**: 거래대금·스크리닝·주문 지정가는 **1단 원본가**, 지표·수익률·스윙은
   **2단 수정주가**. 컬럼 접두사로 구조적으로 분리한다 (§2.3).
3. **2단 거래량 사용 금지**: 2단 거래량은 조정돼 있다(1,147종목). 통합 캐시에 **싣지 않는 것**으로
   실수를 원천 차단한다 (§2.3).
4. **생존편향 차단 유지**: 유니버스는 1단 일별 스냅샷의 합집합이다. "현재 상장 종목" 리스트를
   어떤 단계에서도 쓰지 않는다.
5. **보간 금지**: 결측·이상은 메우지 않는다. 제외하거나 예외를 던진다.

## 2. 데이터 접근 계층 (통합 캐시)

### 2.1 문제

현재 로더는 파일 단위다 — 1단은 일자별(1,857 파일), 2단은 종목별(3,136 파일).
백테스트는 "전 기간 × 전종목" 패널을 요구한다. 매 실행마다 5,000개 파일을 열고 조인·플래그 계산을
반복하면 파라미터 스윕이 불가능해진다.

### 2.2 규모 실측 (2026-07-28)

| 대상 | 파일 수 | 행 수 | 메모리(deep) | 전량 읽기 |
|---|---|---|---|---|
| 1단 스냅샷 | 1,857 | 약 4,680,000 | 약 0.85GB | 약 5초 |
| 2단 수정주가 | 3,136 | 약 4,834,000 | 약 0.23GB | 약 2초 |

> 1단 메모리는 `ticker`·`market`이 object dtype이라 부풀어 있다. 캐시에서 `category`로 바꾸면
> 크게 줄어든다. 조인·플래그 계산까지 포함해도 빌드는 **1분 이내**로 끝난다는 뜻이며,
> "무거워서 캐시가 필요하다"가 아니라 **"매 실행 반복을 없애고 스키마를 한 곳에 고정하기 위해"**
> 캐시를 둔다. 이 구분이 캐시 설계를 단순하게 유지하는 근거다.

### 2.3 통합 패널 스키마 (추천)

**하나의 롱포맷 패널**을 만든다. 키는 `(date, ticker)`이며 **1단 스냅샷의 행 집합이 곧 패널의 행 집합**이다.
2단은 왼쪽 조인으로 붙인다 — 2단이 1단의 완전한 상위집합임이 실측으로 확인됐으므로(스펙 §0) 결손이 없고,
1단에 없는 이전상장 구간은 조인 과정에서 **자동으로 절단**된다. 스펙 §8.2의
"2단은 1단에 (티커, 일자)가 있는 행만 쓰는 것이 기본값"이 구조로 강제되는 셈이다.

| 컬럼 | dtype | 출처 | 비고 |
|---|---|---|---|
| `date` | datetime64[ns] | 1단 파일명 | |
| `ticker` | category | 1단 | |
| `market` | category | 1단 | KOSPI / KOSDAQ |
| `open, high, low, close` | int64 | 1단 | **원본가**. 주문 지정가·체결 판정용 |
| `volume` | int64 | 1단 | |
| `value` | int64 | 1단 | 거래대금. 스크리닝의 핵심 |
| `change_rate` | float64 | 1단 | % 단위 (pykrx 반환값 그대로) |
| `market_cap` | int64 | 1단 | |
| `shares` | int64 | 1단 | |
| `adj_open, adj_high, adj_low, adj_close` | float64 | 2단 | **수정주가**. 지표·수익률·스윙용 |
| `is_halted` | bool | 파생 | `volume == 0` → 매매 불가 |
| `no_regular_session` | bool | 파생 | `volume > 0 AND low == 0` → 고저 계산 제외 |
| `is_shares_jump` | bool | 파생 | 상장주식수 전일 대비 급변 → 기준봉·신규 진입 제외 |
| `is_unadjusted_action` | bool | 파생 | 수정계수 미반영 액션 → 수익률·스윙 제외 |
| `is_limit_up_close` | bool | 파생 | 상한가 마감 → 매수 미체결 판정 |
| `is_limit_down_close` | bool | 파생 | 하한가 마감 → 매도 미체결 판정 |
| `is_last_seen` | bool | 파생 | 1단 최종 등장일 → 폐지 청산 트리거 |

**`adj_volume`은 싣지 않는다.** 2단 거래량은 1,147종목에서 조정돼 있어 거래대금·유동성 계산에 쓰면
신호가 오염된다. 컬럼을 만들지 않으면 잘못 쓸 수 없다.

**`adj_*` 접두사**로 축을 구분한다. 접두사 없는 가격 컬럼은 언제나 원본가다.

### 2.4 저장 형태와 무효화 (추천)

```
storage/cache/panel/
├── {YYYY}.parquet        # 연도별 파티션 (8개)
└── _build_meta.json      # 빌드 지문
```

- **연도별 파티션**: 개발 중 부분 구간만 로드해 반복 속도를 올리고, 증분 갱신 시 당해 연도 파일만
  다시 쓴다. 단일 파일도 성능상 문제는 없지만(§2.2) 파티션이 부분 로드를 공짜로 준다.
- **`_build_meta.json` 지문**: 1단 파일 수·최종 일자, 2단 파일 수, 티커 수, 행 수, 스키마 버전, 빌드 시각.
  로더는 현재 `storage/` 상태와 지문을 대조해 **어긋나면 예외**를 던지고 재빌드 명령을 안내한다.
  자동 재생성하지 않는다 — 조용한 재생성은 "내가 보던 결과가 어느 데이터에서 나왔는가"를 흐린다.
- `storage/cache/`는 이미 `.gitignore`에 있다. 캐시는 언제든 재생성 가능한 파생물이다.

### 2.5 로더 API (추천)

`src/krx_sprint/panel/` 신설.

- `build_panel(...) -> BuildSummary` — 1·2단을 읽어 패널과 지문을 쓴다
- `load_panel(start: date | None, end: date | None, tickers: Collection[str] | None) -> pd.DataFrame`
  — 지문 검증 후 필요한 연도 파일만 읽어 반환
- `load_trading_days() -> list[date]` — 거래일 캘린더(1단 수집 일자). 결제일 계산(§8.2)에 쓴다

CLI는 `scripts/data/build_panel.py`. 실행 명령어는 `docs/COMMANDS.md`에 추가한다.

### 2.6 플래그 판정 로직의 단일화 (중요)

`is_shares_jump`·`is_unadjusted_action`은 이미 `collect/quality.py`(`SharesJumpTracker`)와
`collect/adjusted_quality.py`(`check_action_continuity`)가 쓰는 판정식과 **같은 규칙**이다.
빌더가 규칙을 복제하면 두 곳이 조용히 갈라진다. 판정식을 순수 함수로 추출해 품질 리포트와
패널 빌더가 **같은 함수를 호출**하게 하고, 두 경로의 결과가 일치함을 테스트로 고정한다.

## 3. 수집 단계에서 넘어온 처리 규칙의 코드화

스펙 §8.1·§8.2에서 확정된 규칙이다. 어느 것 하나라도 빠지면 성과가 조용히 부풀려진다.

| 규칙 | 판별식 | 실측 규모 | 소비 지점 | 미적용 시 |
|---|---|---|---|---|
| 거래정지일 매매 불가 | `volume == 0` | 169,623행 (3.61%) | 체결 판정(§7) — 진입·청산 모두 불가 | 체결 불가능한 거래를 체결로 가정 |
| 상장주식수 급변일 제외 | 전일 대비 `shares` 변동 ≥ 10% | 3,345건 | 기준봉 판정(§5.1)·신규 진입(§7.2) | 감자·분할을 급등으로 오인 (최대 +29,948%) |
| 수정 미반영 액션 제외 | 2단 변동 ≠ 공시 등락률 (급변일 트리거) | 16건 | 수익률·스윙(§5.2), 해당 트레이드 무효 처리 | 최대 300배 가짜 갭 |
| 1단 최초 등장일 이전 절단 | 1단에 없는 (티커, 일자) | 43종목 28,811행 | 패널 조인에서 구조적 배제(§2.3) | 최대 −82% 가짜 수익률 |
| 정규장 미형성 고저 제외 | `volume > 0 AND low == 0` | 11행 | 스윙·전저점 계산(§5.2) | 가짜 전저점 |

추가로 이 문서에서 새로 정의하는 규칙:

| 규칙 | 판별식 | 근거 |
|---|---|---|
| 상한가 마감일 매수 미체결 | `change_rate ≥ 29.0 AND close == high AND volume > 0` | 실측 0.23% (§7.3) |
| 하한가 마감일 매도 미체결 | `change_rate ≤ -29.0 AND close == low AND volume > 0` | 실측 0.02% (§7.3) |
| 폐지 청산 | `is_last_seen` (1단 최종 등장일) | 폐지 371종목 (스펙 §8.2) |

### 3.1 두 축 사이의 변환 (설계상 가장 미묘한 지점)

- 지표(이평·전저점·스윙)는 **수정주가 축**에서 계산해야 한다. 원본가로 계산하면 분할 구간에서 깨진다.
- 주문 지정가는 **원본가 축**이어야 한다. 실제 호가는 원본가로 낸다.
- 변환 계수: `k(D-1) = close(D-1) / adj_close(D-1)`. 지표값 `P_adj`를 `P_raw = P_adj × k(D-1)`로 바꾼다.
  액션이 없으면 `k`는 상수이고, 액션일 전후로만 점프한다. **신호일 D-1의 `k`만 쓰므로 PIT가 깨지지 않는다.**
- 거래정지일은 `close = 0`이라 `k`를 만들 수 없다 → 신호일이 될 수 없게 배제한다(`is_halted`).
- 보유 중 손익은 **수정주가 축에서 누적**한다. 그러면 분할·배당락이 자동으로 흡수된다.
  단 미반영 액션 16건은 흡수되지 않으므로, 보유 구간에 걸리면 **그 트레이드를 무효 처리하고 별도로 집계 보고**한다
  (숨기지 않는다. 사전에 알 수 없는 정보라 "전일 청산"은 look-ahead다).

## 4. 테마 동조화 클러스터링

외부 테마 분류(네이버·증권사)는 과거 소급이 불가능해 미래참조 편향이 된다. 쓰지 않는다.
매일의 가격 데이터로 **동조화 클러스터**를 자체 생성한다.

### 4.1 선택지

| 안 | 방법 | 장점 | 단점 |
|---|---|---|---|
| A | 전종목 상관행렬 → 계층적/그래프 클러스터링 | 테마 지도를 항상 유지 | 매일 약 2,500² 상관 × 1,857일. 무겁고 클러스터 해석이 애매 |
| **B (확정)** | **당일 급등 종목만 부분집합으로 잘라 잔차 상관 그래프 → 연결요소** | 하루 수십 종목이라 O(\|S\|²)로 가볍다. "단독 상승은 테마 아님"이 정의에 직접 들어감 | 급등 종목 밖의 테마 맥락은 보지 않음 |
| C | 상관 없이 "같은 날 동반 급등 종목 수"만 사용 | 가장 단순 | 시장 전체 급등일에 전종목이 한 테마가 됨. 시장 팩터 제거 없이는 위험 |

**B로 확정**한다 (§13-④). 시장 팩터 제거를 켠 상태가 기본값이다.

### 4.2 확정안 B의 절차 (신호일 D-1 기준, 모두 D-1까지의 데이터)

1. **유니버스 필터**: 시총 하한, 거래대금 하한, 1단 최초 등장 후 L거래일 경과(신규상장 왜곡 배제),
   `is_halted`·`is_shares_jump` 아님.
2. **급등 집합 S**: 당일 `change_rate ≥ m` (원본가 1단 등락률).
3. **시장 팩터 제거**: 최근 L거래일 수정주가 일간 수익률에서 시장 수익률(해당 시장 동일가중 평균)에 대한
   회귀 잔차를 쓴다. 지수 급등일에 전 종목이 한 테마가 되는 것을 막는 장치다.
4. **엣지**: S 안의 종목쌍 중 잔차 상관 `ρ ≥ θ`.
5. **클러스터**: 연결요소. 크기 ≥ 2(또는 3)만 테마로 인정. **단독 급등은 테마가 아니다**.
6. **대장주**: 클러스터 내 당일 **거래대금(원본가 1단) 1위**.

파라미터: `L`(상관 창), `θ`(상관 임계), `m`(동반 급등 기준), 최소 클러스터 크기.
과최적화 위험이 가장 큰 블록이므로 **파라미터를 넷 이하로 묶고 민감도 분석을 필수**로 한다(§10).

### 4.3 검증 방법

클러스터가 "말이 되는지"는 수치로만 볼 수 없다. 특정 일자(2020-03-19 코로나 저점,
2021-01-11 코스피 최고가 부근, 2023 2차전지 랠리 등)의 클러스터를 종목명과 함께 덤프해
사람이 눈으로 확인하는 절차를 넣는다. `names.csv`는 최신 매핑이라 폐지 종목 이름이 빌 수 있다(정상).

## 5. 기준봉과 N차 하락

### 5.1 기준봉 (원본가 1단)

`value ≥ X × (직전 20거래일 value 평균)` **AND** `change_rate ≥ Y` **AND** `value ≥ V_min`

- 평균 창에 **당일을 포함하지 않는다** (당일을 포함하면 조건이 자기 자신에 희석된다).
- `is_shares_jump` 일자는 **제외**한다. 감자·분할의 등락률 왜곡을 급등으로 오인한다(최대 +29,948%).
- `is_halted` 일자는 제외한다.
- 스펙 §0 실측: 가장 느슨한 조건에서도 7년간 종목의 95%가 한 번은 통과한다. 즉 **기준봉은 종목을
  거르는 장치가 아니라 시점을 찍는 장치**다. `V_min`(거래대금 하한)이 실질적인 종목 필터 역할을 한다.

### 5.2 스윙 정의와 N차 하락 카운팅 (수정주가 2단)

**스윙은 ZigZag로 정의한다** — 임계 `r`% 이상 반전할 때만 스윙 하이/로우를 확정한다.

> **look-ahead 함정**: ZigZag는 본질적으로 사후 확정 지표다. "이 날이 스윙 하이였다"는 사실은
> 이후 `r`% 하락이 나온 뒤에야 알 수 있다. **확정 시점 이전의 스윙을 신호에 쓰면 미래 정보 오염**이다.
> 따라서 카운팅은 **확정된 스윙만** 세고, 진행 중인 하락은 "러닝 하이 대비 하락률"로 별도 관리한다.

- 고저 계산에서 `no_regular_session` 행(고가·저가 0)은 **제외**한다. 가짜 전저점을 만든다.
- `is_unadjusted_action` 행은 수익률·스윙에서 제외한다.
- 1차 하락 = 기준봉 이후 최초 확정 스윙 하이에서 시작된 하락. 반등(스윙 로우 확정) 후 재하락 = 2차.
- **3차 하락 이상 진입 금지** (하드룰).
- **만료**: 기준봉 후 `E`거래일 경과 또는 기준봉 시가 이탈 시 그 기준봉은 무효.
- **카운터 리셋 (확정, §13-②)**: 기준봉 이후 **러닝 하이를 갱신하면 카운트를 0으로 되돌린다**.
  "N차가 깊을수록 위험"의 근거는 고점 갱신 **실패**의 누적이므로, 신고가 갱신은 그 카운터를
  무효화하는 사건으로 본다. 누적 방식은 채택하지 않는다(파라미터로도 두지 않는다 — YAGNI).

## 6. 진입·손절·익절

### 6.1 진입

신호일 D-1 종가 확정 → D일 **지정가 매수 예약**. 지정가 후보(파라미터로 택1):

- (a) `D-1 종가 × (1 − d%)`  ← 가장 단순, 추천 기본값
- (b) 5일선 또는 10일선 (수정주가로 계산 후 §3.1의 `k`로 원본가 환산)
- (c) D-1 저가

지정가는 §8.3의 호가단위로 **내림 정렬**한다(매수는 보수적으로 낮은 쪽).

### 6.2 손절 (대중적 지표만 — 과최적화 방지)

| 후보 | 정의 |
|---|---|
| S1 | 진입 스윙 전저점 이탈 (`전저점 × (1 − 여유%)`) |
| S2 | 5일선 또는 10일선 이탈 |
| S3 | 고정 `−X%` |

**집행 방식 (확정, §13-③): 장중 스톱.** 당일 `low ≤ 손절가`면 그날 체결로 본다.
체결가는 `min(open, 손절가)` — 갭 하락으로 시가가 이미 손절가 아래면 시가에 체결된다.
여기에 §8.5의 1틱 불리를 적용한다. 종가 확인 후 익일 시가 청산 방식은 채택하지 않는다.

### 6.3 익절

익절은 손절의 종속변수다. `익절폭 = 손절폭 × RR`.
백테스트로 승률을 측정하고 **기대값이 최대가 되는 RR을 역산**한다 (예상 프로파일: 고승률·저RR 1:1~1:1.5).
익절 지정가는 호가단위로 **올림 정렬**한다(매도는 보수적으로 높은 쪽).

### 6.4 자금 관리

- 초기 자본 `C`, 동시 보유 `K`종목 (서로 다른 테마 2~3개 — 상관을 낮추기 위함)
- 종목당 배분 = `현재 자산 / K` (예약 미체결이 있으므로 슬롯 관리 필요)
- 같은 클러스터에서 둘 이상 진입 금지 (테마 분산이 전략의 전제)
- 수량은 정수 주(株). 배분액 ÷ 지정가 내림

## 7. 체결 가정 (집행 모델)

일봉만 가지고 있으므로 체결은 **가정**이다. 가정은 언제나 **불리한 쪽**으로 잡는다.

### 7.1 지정가 체결 판정 (D일, 원본가 1단 OHLC)

| 주문 | 판정 | 체결가 |
|---|---|---|
| 매수 지정가 `L` | `open ≤ L` (갭 하락) | `open` — 우리에게 유리한 갭은 그대로 인정 |
| | `low ≤ L < open` | `L` |
| | `low > L` | **미체결** |
| 매도 지정가 `T` | `open ≥ T` (갭 상승) | `open` |
| | `high ≥ T > open` | `T` |
| | `high < T` | **미체결** |

### 7.2 매매 불가 조건

- `is_halted`(거래정지): 진입·청산 모두 불가. 보유 중이면 **강제 보유**가 되며, 해제 첫 거래일에
  조건을 재평가한다. 손절 조건이 이미 충족돼 있으면 해제일 시가에 청산한다.
- `is_limit_up_close`(상한가 마감): 매수 미체결로 본다. 실측 0.23%지만 **테마 대장주 표본에서는
  훨씬 잦다** — 이 처리가 빠지면 "상한가 종목을 원하는 가격에 샀다"는 가짜 수익이 생긴다.
- `is_limit_down_close`(하한가 마감): 매도 미체결로 본다.
- `is_shares_jump`(액션일): **신규 진입 금지**. 그날 원본가 축이 바뀌어 D-1 기준으로 계산한 지정가가
  의미를 잃는다(§3.1).
- `is_last_seen`(폐지): 최종 등장일 종가로 강제 청산. 실제 정리매매는 훨씬 불리하므로
  **폐지 페널티**를 민감도 파라미터로 둔다(기본 0, 시나리오 −30%·−50%).

### 7.3 발생률 실측 (전 기간 1/10 표본 186일 / 470,872행, 2026-07-28)

| 항목 | 건수 | 비율 |
|---|---|---|
| 거래정지 (`volume == 0`) | 16,945 | 3.5986% |
| 상한가 마감 | 1,082 | 0.2298% |
| 하한가 마감 | 91 | 0.0193% |
| 정규장 미형성 | 0 | 0.0000% |

> 거래정지 3.60%는 전수 검사값 3.61%와 일치한다(표본의 대표성 확인). 정규장 미형성은 전수 11행이라
> 표본에 안 잡히는 것이 정상이다.

### 7.4 유동성 상한

주문 금액 ≤ `당일 거래대금 × p` (기본 `p = 0.01`). 초과분은 체결하지 않는다.
대장주는 거래대금이 커서 대부분 무해하지만, 소형주가 대장주로 잡히는 경우를 막는 안전장치다.

### 7.5 같은 봉에서 손절과 익절이 모두 터치될 때

일봉으로는 순서를 알 수 없다. **손절 우선**으로 처리한다 (보수적 표준 가정).
이 케이스의 발생 빈도를 리포트에 반드시 출력해, 결과가 이 가정에 얼마나 의존하는지 보이게 한다.

### 8.5 슬리피지

- 민감도 파라미터로 전 주문에 `s`% 추가 슬리피지를 얹는 시나리오를 돌린다(기본 0).

### 8.6 비용 계산식

```
매수 비용 = 체결가 × 수량 × 수수료율
매도 비용 = 체결가 × 수량 × (수수료율 + 거래세율(결제일, market))
```

원 단위 반올림(내림/올림) 규칙은 CLAUDE.md 반올림 규칙(KRX 원화 = 정수)을 따른다.

## 10. 과최적화 방지와 검증 계획

### 10.1 파라미터 예산

블록별 상한을 정하고 넘기지 않는다: 테마 4개, 기준봉 3개, 스윙·카운팅 2개, 손절·익절 3개, 자금 2개.
"대중적 지표만 쓴다"(스펙 §1)를 지키는 장치다.

### 10.2 기간 분할

- 개발(in-sample): 2019-01-01 ~ 2022-12-31 (횡보·폭락·버블·하락장 포함)
- 검증(out-of-sample): 2023-01-01 ~ 2026-07-27 — **파라미터 확정 후 단 한 번만 본다**
- 시장 국면별 분해 리포트(2020 폭락, 2021 버블, 2022 하락장)로 특정 국면 의존을 드러낸다

### 10.3 민감도

각 파라미터를 ±1스텝 흔들어 성과가 절벽처럼 무너지면 그 값은 과최적화다.
비용 파라미터(수수료·슬리피지·폐지 페널티)도 함께 흔든다.

### 10.4 엔진 정확성 검증 (계약 테스트)

합성 데이터로 **손으로 계산한 값과 일치**하는지 고정한다. 최소 목록:

1. 세율 경계일 6건 + 직전 거래일 6건 → 정확한 세율 선택
2. 호가단위 정렬: 2023-01-25 전후, 코스피/코스닥 차이, 경계 가격
3. 체결 판정 6분기(갭 체결·지정가 체결·미체결 × 매수/매도)
4. 손절·익절 동시 터치 → 손절 우선
5. 거래정지 중 청산 불가 → 해제일 시가 청산
6. 상한가 마감일 매수 미체결
7. 액션일 신규 진입 금지 / 미반영 액션 구간 트레이드 무효
8. 정규장 미형성 행이 전저점 계산에서 빠지는지
9. look-ahead 감시: 신호 산출 함수에 D일 이후 데이터를 넣으면 결과가 바뀌지 않아야 한다
   (D+ 구간을 잘라낸 입력과 전체 입력의 신호가 동일한지 비교)

> 9번이 가장 중요하다. look-ahead는 조용히 들어와 성과만 좋아지므로 **테스트로 감시**한다.

### 10.5 새니티 체크

- 무비용 실행 대비 비용 실행의 차이가 회전율 × 비용률과 맞는지
- 랜덤 진입(같은 유니버스·같은 보유기간) 대비 초과 성과가 있는지 — 없다면 신호에 알파가 없다

```
scripts/backtest/run_backtest.py
```

구현 순서 (각 단계가 "산출물 → 검증"으로 닫히게):

| 단계 | 산출물 | 검증 |
|---|---|---|
| 1 | 통합 패널 빌더·로더 | 패널 행수 = 1단 전수, `adj_close` 결측 0, 플래그 건수가 품질 리포트와 일치 |
| 2 | 비용 모델 (`costs.py`) | §10.4의 1·2번 테스트 통과 |
| 3 | 신호 (`theme.py`·`signals.py`) | 특정 일자 클러스터 수기 확인 + look-ahead 테스트 |
| 4 | 체결·엔진 (`execution.py`·`engine.py`) | §10.4의 3~8번 통과, 합성 시나리오 손계산 일치 |

스펙에 미정의로 남아 있던 항목들이다. 탈락안도 함께 남긴다 — 나중에 "왜 이렇게 했지"를 다시 묻지 않기 위해서다.

## 14. 실행 결과 (2026-07-29)

기본 파라미터로 전 기간을 실행한 결과다. **순기대값이 음수이며, 신호에 알파가 없다.**
기각도 정당한 결론이므로 그대로 남긴다.

### 14.1 성과

| 구간 | 트레이드 | 승률 | 비용 전 손익 | 비용 후 손익 | 누적 수익률 | MDD |
|---|---|---|---|---|---|---|
| in-sample 2019-01 ~ 2022-12 | 868 | 44.12% | **+16,450,184** | **−1,799,612** | −18.50% | −80.48% |
| out-of-sample 2023-01 ~ 2026-07 | 823 | 39.98% | +1,192,052 | −3,640,900 | −35.14% | −68.82% |
| in-sample **무비용** | 868 | 44.12% | +12,465,330 | +12,465,330 | +123.30% | −71.74% |

초기 자본 1,000만원. 무비용 실행은 신호·체결이 동일하고 비용만 0인 대조군이다.

### 14.2 결론 세 가지

**① 비용이 알파를 통째로 먹는다.** in-sample 기준 비용 총액 1,825만원 중 **증권거래세가 1,622만원**으로
수수료(203만원)의 8배다. 평균 보유 3.6일 × 868회전이라 매도금액 합계가 67.7억원에 달하고,
실효 세율 0.2395%가 그대로 곱해진다. 비용/총손익 비율이 in-sample 1.11, out-of-sample 4.05다.

**② 신호에 알파가 없다.** 같은 유니버스·같은 보유기간(4거래일)으로 랜덤 진입한 62.6만 표본과 비교했다.

| | 평균 수익률 | 승률 |
|---|---|---|
| 전략 (비용 전) | +0.36% | 44.1% |
| 랜덤 진입 | **+0.60%** | **48.8%** |

전략이 랜덤보다 **낮다**. 무비용 실행의 +123%는 신호의 실력이 아니라 유니버스 자체의 상승분이다.

**③ 하락장에서 가장 크게 잃는다.** 헷지 목적(§1)과 정반대다.

| 연도 | 트레이드 | 승률 | 비용 전 | 비용 후 |
|---|---|---|---|---|
| 2019 | 143 | 51.0% | +9,668,454 | +7,874,456 |
| 2020 (폭락·급반등) | 248 | 49.2% | +16,985,798 | +10,382,379 |
| 2021 (버블) | 237 | 43.9% | +6,278,414 | −356,832 |
| 2022 (하락장) | 240 | 35.0% | **−16,482,482** | **−19,699,615** |

### 14.3 민감도 (in-sample)

| 설정 | 트레이드 | 비용 전 | 비용 후 | 세금 | 누적 |
|---|---|---|---|---|---|
| 기본 | 868 | +16,450,184 | −1,799,612 | 16,219,841 | −18.50% |
| 손익비 2.5 (회전율↓) | 615 | −4,125,442 | −8,028,699 | 3,473,895 | −80.47% |
| 엄격 기준봉 (5배·15%·100억) | 843 | +14,177,847 | **+810,563** | 11,873,106 | +8.87% |

기준봉을 엄격하게 잡으면 비용 후 플러스로 돌아서지만 4년 누적 +8.87%(연 2.1%)로,
같은 기간 무위험 수익률에도 못 미친다. **파라미터를 흔들어 이 결론을 뒤집지 못했다.**

### 14.4 검증 상태

- 세금 산식 검증: 원장 전 건을 매도금액 × 결제일 기준 세율로 재계산해 **16,219,841원 정확히 일치**
- 무비용 대조군의 트레이드 수·승률이 비용 실행과 동일 — 비용이 진입·청산 판정을 바꾸지 않음을 확인
- 진단: 미체결 1,795건 / 상한가로 놓친 주문 16건 / 손절·익절 동시 터치 31건 / 거래정지 강제보유 0일

### 14.5 다음에 검토할 것 (이번 범위 밖)

이 결과는 "이 전략 정의로는 안 된다"를 말할 뿐, 모든 변형을 기각한 것은 아니다.

- **회전율을 근본적으로 낮추는 방향** — 보유 기간이 길어야 0.24% 세금을 상쇄한다.
  현재 설계는 3.6일 보유라 세금이 구조적으로 이긴다
- 진입 신호를 랜덤 대비 초과하게 만드는 것 — 현재 기준봉·N차 하락 조합에는 예측력이 없다
