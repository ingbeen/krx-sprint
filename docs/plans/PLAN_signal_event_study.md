## 3) 배경/맥락(Context)

### 현재 문제점 / 동기

전략 v1·v2가 모두 기각됐다. 그런데 **두 번 다 고친 것은 "매매 규칙"이었고, 그 밑에 깔린
"이 신호가 미래 수익률을 예측하는가"는 한 번도 직접 측정된 적이 없다.**

v2 원장(76건)을 다시 분해한 결과가 이 작업의 출발점이다.

| 항목 | 값 |
|---|---|
| 수익률 기댓값 | **+0.765% / 트레이드** (승률 40.8%, 평균익 +18.29%, 평균손 −11.31%) |
| 금액 손익 | **−5,782,240원** |
| 평균 투입액 | 이긴 쪽 3,795,627원 / **진 쪽 5,147,434원 (1.36배)** |
| 동일 배분 반사실 | −5,782,240원 → **+2,671,567원** |
| 통계량 | 표준편차 16.36% / 표준오차 1.877% / **t = 0.41** / 95% CI **−2.91% ~ +4.44%** |

두 가지가 동시에 드러났다.

1. **v2의 손실은 자금 배분이 만들었다.** 수익률로는 이기고 있었는데 분할 매수가 "떨어질수록 더 산다"는
   구조라 계속 떨어진 종목에 자본이 몰렸다. 배분만 균등하게 놓으면 부호가 바뀐다
2. **그런데 그 +0.765%는 0과 구분되지 않는다.** 표본 76건, 신뢰구간이 −2.9%~+4.4%다.
   좋다는 증거도 나쁘다는 증거도 없다

v1은 표본이 868건으로 충분했지만 평균 +0.360%(t=1.34)로 유의하지 않았고, **같은 유니버스 랜덤 진입
(+0.60%)보다 낮았다**(설계 v1 §14.2-②).

**즉 "신호에 알파가 있는가"는 두 번의 백테스트로도 판정되지 않았다.** 백테스트는 신호 × 진입 × 청산 ×
자금배분이 뒤엉킨 결과라 원인 분리가 안 되고, 체결된 트레이드만 남아 표본이 수십~수백 건으로 줄어든다.
이벤트 스터디는 **체결 여부와 무관하게 모든 신호**를 세므로 표본이 수천~수만 건이 되고,
매매 규칙이 없어 측정 대상이 신호 하나로 좁혀진다.

### Phase 0 — 정의와 산식을 테스트로 먼저 고정(레드)

> 해당 사유: 초과수익·forward return·표본 단위의 정의가 곧 결론을 만든다. 정의가 흔들리면
> 측정 결과의 해석이 통째로 바뀐다. look-ahead는 구현 후에 넣으면 이미 오염된 채로 통과한다.

**작업 내용**:

- [x] **forward return 정의를 테스트로 고정** — 수정주가 기준, 손계산 예시로 값을 박는다.
      두 가지를 낸다: (a) 신호일 종가 → D+k 종가 (순수 예측력),
      (b) D+1 시가 → D+k 종가 (예약매매로 실제 잡을 수 있는 구간)
- [x] **초과수익 정의를 테스트로 고정** — 같은 날 **유니버스 게이트 통과 종목의 동일가중 평균** 대비.
      시장 전체가 오른 날 전 종목이 알파를 가진 것처럼 보이는 것을 막는다
- [x] **폐지·구간 끝 처리를 테스트로 고정** — forward 창이 데이터 끝을 넘어가면 **마지막 종가까지로 자른다**.
      표본에서 빼면 폐지 종목의 손실이 사라져 생존편향이 생긴다
- [x] **제외 규칙을 테스트로 고정** — 거래정지·정규장 미형성·수정 미반영 액션·상장주식수 급변
      (설계 v1 §3의 처리 규칙)
- [x] **표본 단위를 테스트로 고정** — 같은 날 같은 클러스터의 종목은 독립이 아니다.

- [x] **look-ahead 감시 테스트** — 신호 계층 판정에 D+ 구간을 잘라낸 입력과 전체 입력의 결과가 같아야 한다

| **다중비교** — 계층 7개 × 보유구간 5개면 검정이 35개다. 우연히 유의한 칸이 나온다 | 노이즈를 알파로 오인 | 개별 칸의 t값으로 결론을 내지 않는다. **층을 쌓을 때의 단조 변화**(요소를 더하면 초과수익이 오르는가)를 근거로 삼고, 리포트에 검정 수를 명시한다 |
| **생존편향** — 폐지 종목의 forward 창이 데이터 끝을 넘어갈 때 표본에서 빼면 손실이 사라진다 | 성과 과대 | 마지막 종가까지로 자르고, 잘린 표본 수를 리포트에 낸다 |
| 신호 판정식을 복제해 엔진과 갈라진다 | 측정 대상이 실제 전략과 달라짐 | 기존 `theme.py`·`signals.py` 함수를 호출한다. 새로 구현하지 않는다 |
| 전 기간 클러스터 계산이 느리다 | 반복 실행이 어려워짐 | 백테스트 엔진이 같은 계산을 3분에 끝낸다. 같은 수준을 목표로 하고, 넘으면 구간 인자로 나눠 실행한다 |
| **결과가 "알파 없음"으로 나오는 것** | 전략 재설계가 필요해짐 | 리스크가 아니라 **이 작업의 정당한 결론**이다. v1 §14가 그랬듯 그대로 기록한다 |
