## 실측으로 확정된 것 (재조사 불필요)

스펙 기재 내용 중 **실제 동작이 달라 정정된 항목**이다. 같은 함정을 다시 밟지 않도록 요약해 둔다. 근거와 상세는 스펙 §0·§6·§8에 있다.

- **KRX 로그인 필수** — pykrx는 모든 조회를 인증 세션으로 보낸다. 자격증명은 `.env` 단일 출처이며 없으면 즉시 중단한다
- **휴장일 응답** — 빈 DataFrame이 아니라 **값이 0으로 찬 행**을 반환한다. 빈 결과만 휴장으로 보면 휴장일이 거래일로 저장된다
- **가격 0 판정** — 거래량이 있어도 시가·고가·저가는 0일 수 있다(정규장 미형성). 반드시 있어야 하는 값은 **종가**다
- **당일 데이터** — 장중에도 조회된다. 조회 성공은 확정을 뜻하지 않으므로 확정 시각 게이트로 막는다
- **`market="ALL"`** — 코넥스를 포함한다. KOSPI/KOSDAQ 별도 호출을 유지한다
- **스크리닝은 2단 범위를 못 줄인다** — 어떤 파라미터로도 종목 수가 16% 이상 줄지 않는다(7년이면 거의 모든 종목이 한 번은 급등). 2단은 **전종목 수집**이 확정이며, 스크리닝은 신호 로직(Phase 6)으로 이관됐다
- **티커는 6자리 숫자가 아니라 6자리 영숫자** — 3,135종목 중 78종목이 영문 포함(`03473K`·`0001A0` 형태). 숫자 전용으로 가정하면 수집이 실패한다
- **수정계수는 "조회 시점" 기준** — 조회 종료일 이후에 액션이 발생하면 조회 종료일의 수정 종가가 원본과 어긋난다. "최신일 수정 종가 = 원본 종가"는 그 조건에서만 성립한다
- **KRX 수정주가가 조정하지 않는 액션이 있다** — 감자·병합·분할 일부에서 수정계수가 적용되지 않아 가짜 갭이 남는다(최대 300배). 2단이 모든 액션을 흡수한다고 가정하면 안 된다
- **2단은 1단의 상위집합** — 1단은 코넥스를 제외하지만 2단은 티커 단위 조회라 이전상장 전 이력까지 온다. 43종목 28,811행이 1단 최초 등장 이전 구간이며 가격 축이 달라 경계에서 불연속이다

## Phase 0 — 환경 부트스트랩 ✅

프로젝트가 "품질 게이트가 살아있는 상태"로 시작하는 것이 목표.

1. `git init` + 첫 커밋 → `poetry install`
2. 이관된 유틸(meta_manager, formatting)에 대한 스모크 테스트 작성
3. → 검증: `poetry run python validate_project.py` 통과

**결과**: 환경은 pyenv(Python 버전 고정) + Poetry(패키지 격리, `.venv` 프로젝트 내부) 조합. 실행 명령어는 [COMMANDS.md](COMMANDS.md) 참고.

## Phase 2 — 1단 스냅샷 수집기 ✅

**계획서**: [plans/PLAN_snapshot_collector.md](plans/PLAN_snapshot_collector.md)
**산출물**: `src/krx_sprint/collect/{snapshot,calendar,snapshot_store,meta_store,backfill,names,krx_credentials}.py`, `scripts/data/collect_snapshots.py`

**결과**: 전체 백필 완료. 수집·휴장·실패 합계가 기간 내 전체 평일과 일치하며 실패 0건.

**설계상 지켜야 할 계약**:

- 과거 일자 파일은 **불변**이다. 저장 함수가 기존 파일 존재 시 예외를 던져 구조적으로 막는다. 재수집이 필요하면 **파일을 지운 뒤** 수집기를 다시 실행한다
- 파일 존재 여부가 곧 수집 완료 체크포인트다. 중단해도 재실행하면 이어서 진행된다
- `src`는 pykrx를 import 하지 않는다. 조회 함수를 주입받으므로 테스트가 네트워크 없이 돈다

## Phase 3 — 품질 검증 자동화 (스펙 §8) ✅

**계획서**: [plans/PLAN_snapshot_quality.md](plans/PLAN_snapshot_quality.md)
**산출물**: `src/krx_sprint/collect/quality.py`, `scripts/data/check_snapshot_quality.py`

**결과**: 오류 0건. 경고·정보로 분류된 항목(등락률 초과·정규장 미형성·폐지 종목·상장주식수 급변)은 모두 정상 패턴이며 처리 방침이 스펙 §8.1에 기록돼 있다.

**백테스트로 넘겨야 할 처리 규칙** — Phase 6 설계 시 반드시 반영한다:

- `거래량 > 0 AND 저가 = 0` (정규장 미형성) → 스윙·전저점 계산에서 제외
- 상장주식수가 전일 대비 급변한 일자(증자·감자·분할·병합) → 그날 등락률은 원본가 기준이라 왜곡되므로 **기준봉 판정에서 제외**
- 거래정지일(거래량 0) → 매매 불가 처리

**수기 검증**: 자동 리포트는 내부 일관성만 본다. 외부 시세 대조 절차는 [COMMANDS.md](COMMANDS.md)의 "데이터 진단·수기 검증"에 있으며, 확인된 값은 앵커로 등록해 자동 검사로 편입한다. 대조 결과는 스펙 §3.1에 기록돼 있다.

## Phase 4 — 증분 업데이트

1. 매일 갱신 플로우: 누락 일자만 수집(백필 루프 재사용) → 품질 체크 → git commit & push
2. → 검증: 하루치 증분 실행 후 신규 파일 1개만 추가되고 기존 파일이 변경되지 않음을 확인 (불변 파일 계약)

> 수집기와 품질 리포트는 이미 증분 실행을 지원한다(누락 일자만 처리). 이 Phase의 실제 과제는 **실행 자동화와 확정 시각 확정**이다. 현재 확정 시각 상수는 보수적으로 잡은 값이며, 시간외 단일가 체결이 일별 거래대금에 반영되는 시점을 실측해 조정해야 한다.
>
> **2단 갱신 정책도 이 Phase에서 정한다.** 2단은 새 거래일이 붙을 때마다 전 종목 파일을 다시 써야 하므로 매일 전량 재수집은 비현실적이다(약 1시간). 액션 발생 종목만 선별 재수집하고 나머지는 tail만 갱신하는 방식을 검토한다 — 상장주식수 급변은 1단으로 감지할 수 있다.

  플래그 건수가 1·2단 품질 리포트 수치와 전부 일치(거래정지 169,623 · 급변 3,345 · 수정 미반영 16 · 정규장 미형성 11)

**실행 결과 — 전략 기각.** 상세는 [백테스트_설계_v1.md](백테스트_설계_v1.md) §14.

- **비용이 알파를 통째로 먹는다**: in-sample 비용 전 +1,645만 → 비용 후 −180만.
  비용 1,825만원 중 증권거래세가 1,622만원(수수료의 8배)이다. 평균 보유 3.6일 × 868회전 구조에서
  실효 세율 0.24%가 이긴다
- **신호에 알파가 없다**: 같은 유니버스·같은 보유기간 랜덤 진입(평균 +0.60%, 승률 48.8%)이
  전략(+0.36%, 44.1%)보다 낫다. 무비용 실행의 +123%는 유니버스 상승분이지 신호의 실력이 아니다
- **하락장에서 가장 크게 잃는다**: 2022년 비용 후 −1,970만. 헷지 목적과 정반대다
- 파라미터 민감도로도 뒤집히지 않았다 (최선의 설정이 4년 +8.87%)

**순서 결정**: 전략 계층을 Phase 4(증분 업데이트)보다 먼저 진행한다. 프로젝트의 핵심 미지수는
"비용 차감 후 순기대값이 양수인가"이고, 백테스트 개발 중에는 데이터가 정적이라 2단 갱신 비용을
반복해서 낼 일이 없다. 증분 자동화는 실전 운용 전 과제다.

**설계에서 확정된 외부 사실** (재조사 불필요, 출처는 설계 문서 부록):

- **증권거래세는 결제일(체결일 + 2 거래일) 기준**이며 표본 구간에서 여섯 번 바뀌었다.
  거래일 캘린더로 환산한 경계가 증권사 공지 3건과 일치함을 확인했다
- **호가가격단위는 2023-01-25에 개편**됐고, 개편 전에는 코스피·코스닥이 달랐다
- 매매 수수료 기본값은 보수적으로 0.015%로 고정한다

**넘겨받은 처리 규칙은 통합 패널의 플래그 컬럼으로 박는다** — 거래정지·정규장 미형성·
상장주식수 급변·수정 미반영·상한가/하한가 마감·최종 등장일. 문서에만 있으면 소비 코드가 빠뜨린다.

> **2단 갱신이 패널 빌드의 선행 조건이다.** 2단이 1단의 마지막 거래일을 덮지 못하면 빌드가
> 중단된다. 2단 수집기는 미수집 종목만 받으므로 1단 증분 후에는 전량 재수집이 필요하며,
> 이 비용을 줄이는 것이 Phase 4의 "2단 갱신 정책" 과제다.

**2단에서 넘겨받은 처리 규칙** — 스펙 §8.2 참고:

- 수정 미반영 액션 일자(16건 유형) → 수익률·스윙 계산에서 제외
- 1단 최초 등장일 이전 구간(43종목) → 유니버스 밖이므로 절단
- 2단 시계열은 1단 스냅샷에 (티커, 일자)가 있는 행만 사용하는 것이 기본값

## 원칙
