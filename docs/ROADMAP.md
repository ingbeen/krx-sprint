# krx-sprint 구현 로드맵

> 데이터 수집 단계의 구현 순서. 설계 근거는 [데이터수집_스펙_v2.md](데이터수집_스펙_v2.md) 참고.
> 각 Phase는 "산출물 → 검증"으로 닫히며, Phase 1부터는 docs/CLAUDE.md 규칙에 따라 계획서를 작성한 후 진행한다.
> 작성일: 2026-07-26

## Phase 0 — 환경 부트스트랩

프로젝트가 "품질 게이트가 살아있는 상태"로 시작하는 것이 목표.

1. 압축 해제 → `git init` + 첫 커밋 → `poetry install`
2. 이관된 유틸(meta_manager, formatting)에 대한 스모크 테스트 작성
   - 이유: 테스트가 0개면 pytest가 실패해 validate_project.py 게이트가 작동하지 않음
3. → 검증: `poetry run python validate_project.py` 통과 (Ruff + PyRight + Pytest 모두 green)

## Phase 1 — 검증 게이트 (스펙 §3.3, 선행 필수)

수집 코드를 짜기 전에 pykrx의 실제 동작을 실측으로 확정한다. 결과에 따라 스펙이 바뀔 수 있으므로 가장 먼저 한다.

1. 스팟체크 스크립트 작성 (`scripts/data/`)
   - 게이트 1: 한진해운(117930)이 2016년 일별 스냅샷에 존재하는가
   - 게이트 2: 117930의 2단 개별 조회(`get_market_ohlcv`, adjusted 양쪽)가 데이터를 반환하는가
   - 게이트 3: `market="ALL"` 건수 vs KOSPI+KOSDAQ 합산 건수 (코넥스 포함 여부)
   - 부가 실측: pykrx 최신 버전 로그인 경고 여부, 거래정지일 OHL=0 동작, 당일 데이터 확정 시각
2. → 검증: 게이트 결과를 스펙 §0 실측 항목에 기록, 실패 시 대응 서브루틴 설계 반영

## Phase 2 — 1단 스냅샷 수집기

1. 단일 일자 수집 함수: KOSPI/KOSDAQ 각각 OHLCV+시총 조회 → 티커 조인 + market 라벨 → 스키마 검증 → `storage/snapshots/{YYYY}/{YYYYMMDD}.parquet` 저장
   - → 검증: 특정 일자 1개 수집 후 컬럼·dtype·건수·티커 6자리 보존 확인 (스키마 테스트)
2. 백필 루프: 누락 일자 판정(파일 존재/휴장/실패 구분) + 지수 백오프 재시도 + 요청 간 지연 + names.csv 갱신
   - → 검증: 2019년 1월 한 달 시범 수집 → 영업일 커버리지·휴장 판정 확인
3. 전체 백필 실행 (사용자, 약 6,800회 호출 ≈ 2시간, 중단돼도 재실행하면 이어짐)
   - → 검증: Phase 3의 품질 리포트로 전체 확인

## Phase 3 — 품질 검증 자동화 (스펙 §8)

1. 검증 리포트 스크립트: 영업일 커버리지 / 이상치(음수·고가<저가·등락률 상하한 초과) / 거래정지 패턴 구분 / 시총 검산(샘플) / 폐지 종목 보존 재확인
2. → 검증: 전체 백필 데이터에 대해 리포트 실행, 발견된 이슈는 스펙에 처리 방침 기록 후 해소

## Phase 4 — 증분 업데이트

1. 매일 갱신 플로우: 누락 일자만 수집(백필 루프 재사용) → 품질 체크 → git commit & push
2. → 검증: 하루치 증분 실행 후 신규 파일 1개만 추가되고 기존 파일이 변경되지 않음을 확인 (불변 파일 계약)

## Phase 5 — 스크리닝 + 2단 수정주가

1. 기준봉 후보 스크리닝: 거래대금 급증 × 상승률 조건(파라미터, 느슨하게) → 관심 종목/기간 추출
2. 2단 수집: 통과 종목만 `get_market_ohlcv(adjusted=True)` → `storage/adjusted/{ticker}.parquet`
3. → 검증: 2단 정합성 — 최신 일자의 수정 종가 = 원본 종가 일치, 분할·증자 일자 연속성(가짜 갭 없음)

## Phase 6 — 후속 (별도 설계 문서 작성 후)

테마 동조화 클러스터링 → 기준봉·N차 하락 신호 로직 → 백테스트 엔진(비용·상한가·미체결·생존편향 반영).
데이터 수집이 안정화된 후 별도 스펙 문서로 설계한다.

## 원칙

- Phase 1(실측)이 끝나기 전에 수집기 본체를 만들지 않는다 — 실측 결과가 설계를 바꿀 수 있다.
- 스크립트 실행(특히 KRX 호출)은 항상 사용자가 한다. AI는 코드 작성과 실행 안내만 담당.
- 과거 일자 스냅샷 파일은 불변 — 재작성이 필요해 보이면 스펙 §7.1 근거를 먼저 재검토한다.
